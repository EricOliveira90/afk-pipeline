### #211 — who owns role write-scope enforcement

Role write-scope shipped as a seam with no caller. Decision D4 specifies
it and #72's solution text promises it; no slice declares it. Three
outcomes are acceptable — #91 takes it, #96 takes it, a named follow-up

**Why it is first: delay decides it by default.** The wave order is
1:#84, 2:#195, 3:#85/#86/#193, 4:#91/#132, 5:#96, and the run is in wave 3

follow-up owns it) stays available indefinitely, because it changes no
slice's contract. So this is not an emergency; it is a cheap answer whose
option set shrinks. Answer it through the babysit channel today and the
question is closed on the best terms.

### #220 — the gate-command classification trade

A gate killed for silence is blamed on the candidate's code. The measured
cost of that wrong blame was ~$32 and 13.5 hours of run wall-clock plus an
`afk adopt` recovery; the worst case of the fix is up to 30 extra minutes
of wall clock on a suite that was going to fail anyway. The recorded costs
are lopsided, and the trigger was a **sleeping host** — the normal case
for a laptop running AFK overnight, not an exotic one.

Two things make this a decision rather than a ticket:

- It **contradicts a live PRD 4 implementation decision** (#72: "a timeout
  alone is not infrastructure"), so it needs a PRD amendment entry, not
  only the ADR 0041 amendment already in its criterion 7. Land the fix
  without it and the next contract evaluator refuses a candidate for
  implementing it.
- The **log-tail half is splittable and startable now** — carrying the
  gate log tail into the failure detail the way `prepare` already does via
  `outputTail` changes no classification and contradicts nothing. It is
  also the half that would have let a human read this failure in minutes.

## 6. PRD 4 merges to main one wave at a time (2026-09-10)

**Decision.** PRD 4 does not wait for a single all-slices merge. Each wave
merges to main as it completes, and `feat-claude-code/afk-v2-acceptance-scope-gates`
re-bases onto main after each one.

**Why: the two lanes are already diverging in both directions, and the
divergence is growing.** Measured on 2026-09-10:

- **Feature branch ahead of main by four ADRs.** `docs/adr/` on main stops
  at `0059-busy-probe-deferral-requires-an-open-command.md`. The feature
  branch carries `0060-parser-contracts-declare-regression-surfaces`,
  `0061-a-refused-negotiation-artifact-is-informed-once-before-it-is-terminal`,
  `0062-a-contract-revision-round-carries-its-delta-and-names-its-pair` and
  `0063-a-wall-clock-budget-cannot-fail-a-gate`. Four decisions the rest of
  the repo cannot cite, including 0062, whose fix (`dc0e270`) is what #196
  closes on.
- **Main ahead of the feature branch.** #233's preflight fix landed on main
  only (`2d9d587`), as did #143, #144 and #206. Every day the branch stays
  open, the run is verifying against a main it does not have.

A single terminal merge makes both directions worse at once, and it also
makes the conflict it has to resolve maximal — #219 is already
`CONFLICTING`. Wave-at-a-time keeps each merge the size of one wave's diff,
and it releases the riders below on a real schedule instead of one cliff.
