### If REVISE, specific gaps:
- New patterns / deps / schema — "`Extend the versioned canonical contract-negotiation artifacts with machine-validated finding lifecycle, planner contest evidence, evaluator disposition, revision citation, and exhaustion classification fields`": this names concepts but not an executable schema or transition contract. It does not identify which artifact the planner writes, which artifact the evaluator writes, their versions/keys/types, or the legal role-owned transitions; "`held`" is required although it is not one of `OPEN`, `RESOLVED`, `CONTESTED`, or `WITHDRAWN`. The current evaluator-owned `contract-review.json` is deleted immediately before evaluator invocation, so it cannot implicitly carry a planner response. This violates boundary explicitness and UAT-verifiability; define the canonical artifact ownership and exact state/disposition transition matrix, including terminal-state reactivation rules.
- Test plan — "`Given an evaluator has resolved a finding after its clear-condition is met, when a later artifact makes that ID active again`": under the same plan's hard two-planner-round cap, a finding resolved by the second evaluator has no later evaluator artifact or planner round in which this scenario can occur. A pure validator test could feed a synthetic history, but then "`no planner invocation receives it as fresh work`" is not observed. This violates UAT-verifiability; exercise the issue's runnable sequence instead: round 1 evaluator opens the ID, round 2 planner records the clear-condition response, and round 2 evaluator reactivates that ID, which must fail before any third planner invocation.
- In scope — "`preserve each attempt and its resolved/unresolved identity`": no test-plan entry inspects archived attempts after lifecycle transitions. Existing archive coverage can still pass by preserving only each attempt's raw verdict while losing the computed resolved/unresolved identity promised here. This violates falsifiability; extend an existing archived-round scenario to assert each archived machine record's finding ID, lifecycle state, and resolved/unresolved classification across both rounds and evaluator retries.

An implementation could escalate on a held advisory or choose either classification for mixed blockers while passing both pure cases. This violates falsifiability; qualify impasse by severity and add observable advisory-only and mixed-state cases with an explicit classification precedence.

ADR 0028`": the verification list runs `test:fast` and `test:heavy:orchestrator`, but `test:fast` excludes wave tests and ADR 0028 lock-refusal accounting lives in `src/wave-migrations.test.ts`, under `pnpm run test:heavy:wave`.
