## Patterns and test harness

- FACT: `src/post-qa-gates.test.ts` exercises `QA_WINDOW_ARTIFACT_NAME`/`reviewArtifactViolations` using `describe("[behavior:B-03] ...")`-style behavior-ID-tagged blocks — the naming convention new cleaner tests should follow.
- FACT: PRD's own "Testing decisions" section (`prd.md:664-696`) specifies: unit-test the pure functions first (`parseClean`, `{changedFiles}` expansion, suppression counter, `parseCleanerEscalation`, `cleanerRoundsRemaining`); extend `src/qa-orchestration.test.ts`'s existing "final evaluation and reuse" fixture (cited at `:3297`) with new `it`s for the stub-cleaner branch, using fake gates as `node -e` package.json scripts per its `:3607` convention; verification command is `pnpm run typecheck && pnpm test:fast` plus `pnpm run test:heavy:qa` — never the full suite for this slice's own iteration. This matches this repo's `CLAUDE.md` "Test loop discipline" section (spawned-scenario placement order: unit → existing spawned scenario → new fixture slice → new spawn as last resort; heavy suites split across two files each).
- INFERENCE: Because `qa-orchestration` already hosts the final-evaluation fixture the cleaner conceptually extends (candidate-approval → post-approval stage → final evaluation), new cleaner-stage `it`s most likely belong in that same spawned scenario rather than a new spawn, per the PRD's own stated approach and the repo's stated test-placement order.
- FACT (ADR 0050, `docs/adr/0050-focused-scope-revision-is-bounded-per-round.md`): applies ADR 0041 ("choose the branch that cannot loop") to bound a per-round retry grant; the defect precedent was an uncapped `while(true)` loop. Governs why `MAX_CLEANER_ROUNDS` must be an enforced comparison, not just an incremented counter.
- FACT (ADR 0051, `docs/adr/0051-a-failed-focused-revision-restores-the-accepted-lock.md`): a failed revision must restore prior authoritative state on **every** exit path (exception, validation failure, evaluator `REVISE`, cancellation), not only the success path — the original bug left state destroyed on every non-success exit because restoration only happened after success. Governs the rigor bar for the cleaner's regression-revert logic: it must restore on every exit, not just the expected regression-detected path.
- FACT (ADR 0057, `docs/adr/0057-guardian-review-rounds-converge.md`): guardian rounds previously had no termination mechanism (one run spent 8 rounds on a non-depleting finding series). Establishes the round-ledger vocabulary (`GuardianRoundPersistence`, append-only rounds, filed-findings carry-forward) that D9's `qualityStages` persistence models.
- FACT (ADR 0063, `docs/adr/0063-a-wall-clock-budget-cannot-fail-a-gate.md`): a wall-clock/cost measurement must never gate pass/fail, because it measures the host machine and an unattended agent's only "fix" is raising the number. Directly governs D1's rule that `clean` gate `expectedCostMs` is for budgeting/reporting only, never a pass/fail condition.
- FACT (ADR 0034, `docs/adr/0034-afk-manifest-and-migration-claims.md`): establishes config-file-driven (not CLI-flag-driven) declarative gating as the repo's precedent — the same rationale D1 uses for `gatePolicy.clean` over a hypothetical `--enable-cleaner` flag.
